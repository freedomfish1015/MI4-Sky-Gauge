# mi4-sky 二次开发指南

这份文件面向接手的开发者/AI：先知道真实入口，再做小范围改动。**手机中的仪表、ESP32 SkyGauge 主表、AI Passport 模拟器是三个不同系统，不能混刷固件。**

## 1. 从哪里开始

1. 阅读 README、KNOWN-ISSUES、ARCHITECTURE，理解当前验证范围。
2. 按 BUILD 在电脑编译 native 核心并运行离线测试；未连接手机也能做大部分逻辑开发。
3. UI 入口 `app/gauge_sdl.py`；布局扩展 `gauge_home.py`；设置交互 `gauge_settings.py`。
4. 需要硬件时，再看 overlay 的 systemd 与 hardware。先读现状、备份、核对哈希；不要整份覆盖旧分区。
5. 使用 development-logs/index.json 找历史证据。日志中的“已修复/待刷/已回退”只代表当时，不是当前状态。

## 2. 数据和进程

```text
OBD BLE ─→ 单一传输所有者 ─→ PID/被动解码 ─→ 仪表快照 ─→ 界面 / LOG
                  ↑ 原始 ELM 查询/回复转发 ↓
              SkyGauge 主表（可选）

IIO 加速度 + QMI/QRTR GNSS ─→ mi4_motiond ─→ /run/obd-motion/state.json
                                               ├→ G值 / 轨迹页面
                                               └→ 同次行程的文件记录

LOG/轨迹文件 ─→ 只读下载目录白名单 ─→ 热点/HTTP ─→ 浏览器或未来小程序
```

`services/motion`、`power`、`charge` 是系统服务，不要在 UI 线程里直接读慢设备、启动 shell 或做阻塞网络请求。界面只取快照/发受限控制请求。文件记录与曲线冻结是两件事。

## 3. 页面和手势怎么改

逻辑布局坐标是 640×360；以3倍栅格化并旋转到1080×1920面板，横向1920×1080像素对应，不是540p放大。修改逻辑坐标即可，不要把触点坐标再次乘3。

- `gauge_home.py`：主页面四角窗口、左右状态条和配色。
- `gauge_settings.py`：页面状态、触摸下/移/起、列表滚动、设置点击。
- `gauge_telemetry.py`：下滑 LOG 曲线、暂停显示和文件记录。
- `gauge_tracks.py`：上滑轨迹、缩放/全览/历史路线。
- `gauge_windows.py`：可选信号、标题、单位和窗口绑定。

默认左滑设置、下滑LOG、上滑轨迹；列表中的上下滑动不能误触左右导航。改命中框时同步改绘制位置和测试，不要只改外观。

渲染依赖静态底图缓存、脏区域重绘、纹理局部上传、渲染/呈现并行。**移动数值或加粗条后必须更新脏矩形并包含发光边界**；否则静态导出正确、实机增量帧丢数字。不要每帧重新创建Pango布局、载入PNG或重画整屏。运行 test_gauge_telemetry / test_mi4_motion，并用真实增量路径验收。

## 4. 增加一个窗口数据类型

1. 在数据源层引入真实信号，使用工程单位，携带有效/过期状态。
2. 在 `gauge_windows.py` 注册稳定 ID、标题、单位与格式；已有 ID 不随便重用。
3. 设置页的窗口选项和当前绑定保持兼容。
4. 在 `gauge_telemetry.py` 的通道映射中按需记录；RaceChrono 导出也要显式加列和来源。
5. 缺失值用 None/无效状态显示 `--`，不要把断线、无GPS、未支持信号伪造为0。
6. 补“缺失/超时/重新连接/配置损坏/切换窗口不重连”测试。

## 5. 扩展 PID 包

`vehicles/catalog/*.vehicle.json` 保留上游 `skygauge.vehicle/1`，由 `native/mi4_compat.c` 桥接原C核心，不要把复杂RPN换算压扁成错误的scale/offset。

老式自定义JSON仍有 `id/name/pids`，入口 `gauge_settings.validate_profile`；只允许Mode01/22只读查询。Mode22也不意味着所有ECU都支持，必须按车型验证，不能把模拟器适配宣称实车通用。

新增车型：复制最相近的原版包 → 新稳定ID → 逐信号验证长度、端序、单位、超时和负响应 → 用fake adapter/回归测试 → 再在停车状态实车验收。未经新授权不要加入ECU写入、清故障码、编程或编码命令。

## 6. BLE 与 Sky 转发红线

当前两种使用方式是手机直连OBD，或手机作为OBD网关供Sky主表查询；不是让手机模仿ESP32 ESP-NOW从机。手机可连接Sky遥测服务的兼容接收代码仍在，但UI已撤销旧从机模式。

`elm_bridge_core.py` 管原始命令/回复、边界和背压；`elm_passive.py` 被动解码；`gauge_elm_forward.py` 接入仪表；`elm327_ble_bridge.py` 提供BLE服务；`elm_radio.py` 有针对连接的低延迟调整。

一个上游连接只允许一个命令所有者，不能仪表轮询和Sky查询交错发出；不能在连接失败时补假数据。广播中保留传统广播包的可见名称以兼容老主表。不要将OTA服务、配对特征或同UUID不同服务当作ELM通道。

新安装主表MAC须通过 `mi4-sky-bind-sky` 显式绑定，仓库中示例地址均为合成地址。连接成功、收到通知、收到有效车况三件事要分开记录。

## 7. G值、GPS 与 LOG

`mi4_accel_autocenter.py` 负责加速度动态分量/自动回中，不依赖陀螺仪来驱动点。不是经过车辆坐标/安装姿态标定的测量仪，不能把显示坐标直接宣称真实车辆纵横向加速度。

G表显示范围2.2g，原始峰值不因显示范围而截断；方向峰值、5秒轨迹/角度包络、视觉平滑分别处理，不用平滑后的值覆盖原始采样。具体算法以 motiond 的 RollingEnvelope、采样输出和测试为准。

GPS通过QMI/QRTR/remoteproc链路，与裸I2C无关。记录必须区分“观测到的卫星”“用于解算的卫星”“已有效定位”；不要仅凭编号猜测北斗。轨迹只接受有效、合理、非重复定位点，无定位不补假坐标。

`gauge_telemetry.Telemetry`：手动文件记录及行程联动；`racechrono_export.py`：按需CSV转换。开始GPS行程后，LOG和GPS同一行程一起开始/结束，仍能查看实时曲线。不要为导出改写原始JSONL/GPX。

## 8. 热点/小程序扩展

看 API.md。单二维码是JSON，不是已发布的小程序码。没有正式AppID；前端权限、平台联网限制、连接热点和下载能力须由小程序开发者真机验证。

保持HTTP只读、文件名白名单、token时效、活动行程保护、Host检查和有界转换。浏览器下载页不依赖CDN。不要开放任意路径下载、任意shell执行或直接把root控制接口暴露到热点。

## 9. 硬件修改和刷机

先做软件/只读检查。boot含首512KiB lk2nd，后面才是Linux Android boot。原厂Fastboot和lk2nd的boot写入语义不同；不能把完整32MiB镜像发给偏移后的逻辑boot。

兔子修复是精确旧aboot的4字节指令补丁，不是通用aboot移植。保留完整哈希、设备/分区大小、USB、电量、电压、备份、单扇区写入与回退保护。默认 `--check` 只读，开机服务的 `--auto` 才按已授权策略执行。不得在CI或普通电脑测试真实写入。

电池OCV单位、WLED、音频、低电量引导与Linux服务各有独立修复；不要为一个功能直接刷旧boot覆盖全部现状。音频已到既定正常增益边界，不继续加硬件增益。详细失败证据见开发历史。

## 10. 提交与验收建议

每次PR写清：改动范围、配置/协议兼容、离线测试、硬件是否在场、是否写分区、可回退点。源码/文档/测试同步提交，二进制放Release。新增素材附许可证和来源。

先通过 `tools/run_tests.py --full` 和 Windows `installer/test.ps1`。UI再验增量绘制与触摸；蓝牙实测双端流量与延迟；GPS到开阔天空验收；电源检查插拔/充电中重启。日志保留失败，不能把Mock测试或工具OKAY当成实机安装完成。

## 11. 已知未完成工作

原厂Fastboot缺失boot大小导致安装阻断；其他屏幕/触控未适配；新机清空安装未完整验收；镜像逐字节可复现链路仍有差距；事件核心未全面连接视觉动作；小程序尚未发布。见 KNOWN-ISSUES 与 REPRODUCIBILITY，不应通过删保护或改“stable”标签掩盖。

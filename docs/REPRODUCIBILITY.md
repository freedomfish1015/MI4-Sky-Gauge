# 来源与可复现性

本次是把工作系统的项目代码整理为可维护源树，不伪造过去缺失的Git历史。

## 可以从源码构建/测试

- PID/事件FFI库：当前仓库已vendor所需C源、头文件、上游测试向量和cJSON1.7.19，主机编译及回归验证。
- Windows安装器：完整C#源码、便携PowerShell脚本和20项离线测试。
- 应用/服务：来自已清理R2运行副本，不使用开发目录里未部署的混合版本；合成设备地址替代示例中的开发机地址。source-provenance.json保留原始/导出哈希和变换说明。
- 内核：提供完整工作源码归档、对应上游commit、配置、改动补丁、新增驱动与最终DTB的DTS文本。实际boot内的内核前缀与本地zImage一致。
- lk2nd：提供实际工作源码快照；原本地树没有.git，不能编造commit，以归档SHA标识。

## 尚未证明/不包含

- 相同源码不保证不同编译器、时间、配置、打包器产生相同boot；历史lk2nd二进制的全部构建参数仍需复核。
- 一些设备树修复曾直接修改boot内DTB，故同时提供最终设备树文本；移植到正常DTS编译链后须重新对比OCV/WLED/音频/显示。
- rootfs-packages.json是版本清单，不是锁定仓库快照。Ubuntu发行版更新、SDL编译选项、ARM本地库和内核模块安装都影响结果。
- rootfs staging只提供离线overlay准备，不声称全自动从Ubuntu base复刻原设备。需要设备固件、系统包、账户权限、模块、initramfs及启动参数。
- 不收录个人整机源tar、原厂aboot、固件/校准分区、用户数据或未授权素材；不凭空承诺厂商闭源组件也已开源。

新增文件或修复请维护metadata/dependencies.lock.json、测试和变更说明。需要重新发布包含GPL组件的二进制时，应提供与该二进制相符的对应源码及构建/安装信息，而不是只链接一个不断变化的上游分支。

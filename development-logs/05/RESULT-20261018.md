结论：尚未修复内置扬声器/3.5mm输出。已实际验证ADSP及APR通信正常，并从本机MIUI备份确认Taiko硬件描述；当前缺少编解码器和板级声卡驱动，不能仅开启CONFIG_SND_SOC_QCOM后宣称成功。

## 已执行的真实设备测试

1. 发现ADSP的`apr_audio_svc` RPMSG/SMD通道存在，但没有绑定驱动。
2. 使用本地现有源码及匹配Module.symvers编译临时外部模块mi4_adsp_probe.ko，内核正常接受版本CRC，无force加载。
3. 临时绑定该未使用通道，只发GET_STATE(0x1290c)、GET_VERSIONS(0x12905)两条只读查询。
4. 实际响应：GET_STATE返回1（就绪），GET_VERSIONS返回11个服务。
5. 收到的APR响应头是24字节，必须按hdr_field的header_size解析；不能硬编码20字节。
   v1探针硬编码20导致的67109121/0个服务不是有效解释，最终结论只使用v2结果。
6. 临时模块已rmmod，通道恢复未绑定，未配置开机加载。外部模块产生的内核taint标记会留至本次启动结束，不表示模块仍在运行。

证据：adsp-probe-v2-result.log、final-state-and-boot-check.log。

## 原系统硬件描述（来自本机boot备份）

inspect_boot_fdt.py提取original-partitions/boot.img中的合法FDT，AC机型描述含：

| 部分 | 原系统值 |
| --- | --- |
| 编解码器 | `qcom,taiko-slim-pgd`，Taiko/WCD9320系列 |
| 声卡 | `qcom,msm8974-audio-taiko` |
| SLIMbus | 基址0xfe12f000，BAM基址0xfe104000，IRQ163/164 |
| PGD elemental address | `00 01 a0 00 17 02` |
| IFD elemental address | `00 00 a0 00 17 02` |
| Reset | TLMM GPIO63 |
| MCLK | PM8941 GPIO15，9.6MHz |
| 静态供电 | PM8941 S2 2.15V、S3 1.8V、L1 1.225V |
| 扬声器供电 | PM8941 boost 5V，按需启用 |

这些是原厂设备树配置，不是本次直接读取的芯片硅ID，也不能直接将旧驱动的电源配置写入主线驱动。
提取文件在stock-fdt/，参考AC描述stock-007e98cd.dts。当前OCV修正版DTB另存current-ocv-fixed-fdt/stock-008e2bd8.dtb。

## 具体驱动缺口

- 当前源码无WCD9320/Taiko codec驱动。已有WCD9335/934x驱动不能作为它的替代。
- 当前源码无MSM8974+Taiko板级声卡驱动，缺PCM前端到Q6 AFE/ADM/SLIMbus后端的完整连接。
- 现有SLIMbus NGD驱动需要验证MSM8974寄存器、BAM DMA和旧固件QMI协议兼容性。
- 之后还需电源/复位/主时钟、SLIMbus PGD/IFD枚举、codec初始化、DAPM/混音路由和低音量真机听音验证。
- 当前只有PipeWire的用户空间设置无法补出这些缺失的内核驱动。

同平台主线开发项目亦记录codec/machine driver缺口：
https://github.com/KorelisLabs/lumia-1520-mainline
原机混音路由参考：
https://github.com/LineageOS/android_device_xiaomi_cancro/blob/cm-14.1/audio/mixer_paths.xml
